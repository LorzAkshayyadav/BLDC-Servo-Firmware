## Layer rules

L2 (`foc/`) and L3 (`motion/`) may only reach hardware through `hal/*.h`, and
`hal/` may not call upward into either -- that boundary is what lets `foc/`
and `motion/` compile and run against `test/host/hal_stub.c` on a PC.

Two files in `hal/` call upward anyway, and both are deliberate:

| File | Calls | Why |
|---|---|---|
| `isr_vectors.c` | `foc_isr()` | The vector body is register work (clearing `ADC1->ISR`, testing the watchdog flags first per risk R3) and must not live in L2 |
| `hal_safety.c` | `foc_reset_integrators()`, `motion_reset_integrators()`, `scope_log_freeze()` | Arch section 5.5 steps 3 and 6 of `hal_safe_state()`. A direct call cannot be silently absent the way a forgotten registration callback could be — omitting the integrator reset makes re-enable trip instantly, and that failure mode is worse than the layer crossing |

No other upward call is permitted. `Tools/layer_check.py` enforces exactly
these two files as the only ones allowed to include `foc/foc.h`,
`foc/scope_log.h`, or `motion/motion.h` from within `hal/`.

## Notes

- The tree is flat at the project root — no `src/` wrapper. `app`, `motion`,
  `foc`, `config`, `common`, and `hal` are the module directories (all
  lower-case: `CMakeLists.txt` globs and include paths depend on this exactly
  matching, and only Windows' case-insensitive filesystem forgives a
  mismatch); `torque/` from the original plan is named `foc` here.
- `platform/` is the real, single copy of everything STM32CubeMX owns —
  `BLDC_18A_STM32H743.ioc`, `Core/`, `Drivers/`, `cmake/`, the startup file,
  and the linker script all live there now (moved from the project root).
  CubeMX generates `Core/`, `Drivers/`, `cmake/`, the startup file, and the
  `.ld` file as siblings of wherever the `.ioc` sits, so opening
  `platform/BLDC_18A_STM32H743.ioc` in CubeMX and hitting "Generate Code"
  writes back into `platform/` from now on. Nothing under `platform/` is
  ever hand-edited except the three build files below.
- Three build files carry a root-relative path into `platform/` and needed
  updating for the move: root `CMakeLists.txt`
  (`add_subdirectory(platform/cmake/stm32cubemx)`), `CMakePresets.json`
  (`toolchainFile` → `platform/cmake/gcc-arm-none-eabi.cmake`), and both
  `platform/cmake/gcc-arm-none-eabi.cmake` / `starm-clang.cmake` (linker
  script path → `${CMAKE_SOURCE_DIR}/platform/STM32H743xx_FLASH.ld`).
  `platform/cmake/stm32cubemx/CMakeLists.txt` needed no edit — its
  `../../Core/Inc`-style paths are relative to its own folder and resolve
  correctly at the new nesting depth; it's CubeMX-regenerated anyway.
- `CMakeLists.txt` sources/includes `app/`, `motion/`, `foc/`, `hal/`
  (`*.c` glob, plus `common/fixed.c` and `common/contracts.c` explicitly)
  and adds the project root plus `app/`, `motion/`, `foc/`, `config/`,
  `common/`, `hal/` to the include path. The root itself is on the include
  path because every file uses root-relative quoted includes
  (`#include "hal/hal.h"`, `#include "foc/transforms.h"`, ...) rather than
  bare filenames.
- Still open: `app/main.c` and `Core/Src/main.c` both will want to own
  `int main(void)` once `app/main.c` gets real content — that collision is
  unresolved.
- Most files under `app/`, `motion/`, `config/control_params.h`, and
  `test/host/` are still a skeleton: include guards and a one-line header
  comment only, no declarations or logic yet. `foc/` now has function
  declarations wired to match what `foc_isr.c` actually calls (see
  IMPLEMENTATION_SPEC.md), but the `.c` bodies behind those declarations are
  still one-line stubs — the real DSP/control-law work is unmeasured and
  belongs to bring-up stages 3–4, not to this scaffolding pass.
